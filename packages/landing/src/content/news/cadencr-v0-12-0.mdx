**CadencR v0.12.0 brings more of your everyday development workflow into the workspace: browsing, editing, running commands, and working with the agents you choose.**

The embedded browser gains the controls you need to check your work. The terminal moves to CeleriTTY, and the editor can run your own Neovim. Local provider connectors extend the plugin story beyond themes, so you can bring another coding agent into the same workflow.

## A browser you can keep working in

Build a page with an agent, open it beside the conversation, and check how it behaves at different screen sizes. Responsive viewport controls let you inspect layouts while keeping screenshots and element annotations aligned with what you see.

The browser also gains the everyday tools that make it easier to stay in the workspace:

- History, bookmarks, and address-bar suggestions to return to useful pages.
- Tab organization and lazy restoration of saved tabs.
- Find-in-page and zoom controls.
- Downloads with progress, pause, resume, cancel, and reveal-in-folder actions.
- Popup controls and familiar secondary-click link handling.
- Browser profiles and site controls for permissions, stored data, and agent access.

Together, these additions keep more of the build-and-check loop beside the code and the conversation.

## Your terminal, your Neovim

The terminal now uses **CeleriTTY**, with WebGPU rendering and a Rust/WASM engine. Shell sessions reconnect across pane changes, split terminals keep their place, and copy/paste stays close at hand. If you use Alacritty, CadencR reads its font, colors, cursor, and scrollback settings and follows changes live.

For modal editing, enable **Neovim in Settings → Editor**. CadencR runs a real Neovim instance with your configuration and plugins. Open files from the file tree or quick-open dialog, follow file-and-line references, and use the editing habits you already know while your agent works alongside you.

Thanks to [@edjubert](https://github.com/edjubert) for the CeleriTTY and Neovim integration, and for the provider/model selection fixes included in this release.

## Bring your own local provider

Custom themes introduced a way to shape CadencR from a project inside the app. **v0.12.0 extends that approach to local ACP provider connectors.**

Use **Add provider** to create a connector project with instructions your coding agent can work from, or import an existing Git repository containing a built connector. You can develop the integration in the same workspace where you will use it.

Once the connector is built and registered, restart CadencR to discover its models. Supported session settings and resume capabilities come from the connector, allowing it to participate in the conversation workflow with its own controls.

This release focuses on local authoring and use. Public marketplace browsing and publishing remain planned for a later release.

## More control over everyday agent work

**Codex profiles** let you name and reuse configurations, choose an optional native `config.toml`, and set environment overrides. Manage profiles in Settings, choose a default, or select one for a conversation from Info.

Long conversations receive a performance pass across search, large code blocks, nested agent activity, and sidebar rendering. Large outputs open through explicit previews, with Bash output keeping its command card and access to earlier lines.

The sidebar makes activity easier to read: a blue ring marks an agent at work, while a green check marks a finished response with unread messages. When a task spans several conversations, archiving can now include its parent and descendants, with counts shown before you confirm.

The release also keeps provider and model selections in sync, corrects Codex parent/subagent routing and completion state, preserves unsaved editor buffers across formatting and disk updates, and clears stale port badges after reconnects. Dependency security updates round out the release.
