**Plugins are coming to CadencR, and v0.11.1 starts with the part of the app you see every day: custom themes.**

This release turns theme customization into a real CadencR workflow. Instead of squeezing colors into a settings form, CadencR gives each custom theme its own project, portable file, editor, and agent.

## Your theme is a project

Start from any built-in or custom theme, give the copy a name, and open it as a dedicated project. The theme file sits in the editor while an agent works beside it, and saved changes repaint the app live so you can evaluate the result in the interface you are actively using.

## The first step toward plugins

Custom themes establish the pattern for CadencR plugins: extensions should be local, transparent, and editable with the same tools and agents you already use for code.

Themes are the beginning of that plugin story. v0.11.1 ships the first user-owned extension experience now, with room for CadencR to grow beyond visual customization without turning extensibility into a separate workflow.

## More control, less maintenance

The release also adds background storage optimization with visible, resumable progress. CadencR removes verified duplicate command output and moves pasted images into durable blob storage without deleting conversations, messages, or authored text. An optional archived-conversation policy can shorten old command output after a configurable quiet period.

Appearance settings now include a searchable monospace-font selector that applies one installed font across terminals, editors, and code snippets. A new customizable `Cmd+Alt+W` / `Ctrl+Alt+W` shortcut cycles branch and worktree behavior directly from the conversation.

Codex reasoning sections remain separated while streaming, browser comment selection recovers after a full refresh, horizontal resize handles are easier to grab, and Fast mode stays compact in narrow agent panes.
