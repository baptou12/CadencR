## Send and steer

Write the result you want and the constraints that matter. `Cmd/Ctrl+Enter` sends; plain `Enter` adds a newline. A follow-up sent during an active turn can steer the agent. Watch the prompt's delivery receipt, especially after reconnecting.

Use the send button's scheduling action to open the same editor used by the [Schedules](../schedules/) page. Scheduling requires CadencR to remain running.

## Add context

| Input                  | What it does                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------- |
| `@`                    | Search current project files and insert a file or folder reference                    |
| `@@`                   | Search conversations across registered projects and add a clickable history reference |
| `/`                    | Find provider commands and CadencR orchestration commands                             |
| `$`                    | Insert supported skill references, including CadencR orchestration skills             |
| Paste, drop, or attach | Add images and provider-supported files                                               |

An `@@` reference gives the agent a route to the selected history through Workspace MCP. If the task should continue in that conversation's live checkout, use the offered **reuse worktree** action and check the resulting branch/worktree selection before sending.

### Commands and skills vary by provider

Claude slash commands can appear within a prompt. OpenCode slash commands are anchored at its start. Codex skill references use `$`. CadencR's virtual `cadencr:*` skills accept either `/` or `$` and expand at send time; see [MCP & orchestration](../mcp/).

## Run a shell command with `!`

Start the prompt with `!` to enter shell mode on supported providers:

```text
! npm test
```

CadencR uses provider-native shell execution where available and a worktree-aware local path where needed. Output streams into the conversation and is kept as context for following prompts. Use Stop to cancel a command. The terminal pane remains useful for interactive shell work.

## Select provider, model, and profile

Open the model picker with its button or `Cmd/Ctrl+P` while the composer is focused. Search the catalog, expand a provider group, and star models you use often. Favorites are stored by provider and remain available across conversations.

New conversations use the provider and model from the last accepted manual prompt across projects. Explicit conversation choices take priority. Scheduled or delegated work does not replace that manual-prompt preference.

Provider profiles can change the available model catalog and runtime configuration. Codex supports named profiles, including native `config.toml` and environment overrides. Manage them in **Settings → CLI Providers**; select a conversation profile in its supported session controls.

### Thinking, modes, and Fast

The selected model determines available thinking levels. CadencR remembers applicable choices and clears options the next model does not support. Profile defaults can supply a choice when you have not set one explicitly.

Collaboration and access modes are provider capabilities. Use the modes displayed in the composer; `Shift+Tab` cycles the appropriate control. Supported Codex models also expose **Fast** mode, which uses the priority service tier. A provider may offer other model-specific controls.

## Attachments and images

Accepted types depend on the active provider. Codex can receive supported documents, including PDFs and spreadsheets, through temporary file references. Images appear as previews in the composer and transcript.

Open an image to zoom, pan, navigate attachments, copy, or save it. Unsent images stay with the draft when switching conversations. If an attachment is no longer available during a retry, CadencR reports the problem instead of silently dropping it.
