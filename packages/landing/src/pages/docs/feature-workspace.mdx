A feature workspace holds one conversation and the working context around it. Keep a task here while you ask for changes, inspect files, run checks, and review Git.

## Read the header

The title block includes the conversation title, worktree branch, and setup state. Open the setup details to inspect progress or errors. Setup output persists when you reopen a conversation or reconnect; interrupted setup can be retried.

The header also gives access to conversation information, custom actions, Git controls, and archive actions. Conversation Info exposes runtime details such as the provider profile and connected MCP servers when supported.

## Choose a pane

| Pane     | What you can do                                                                          |
| -------- | ---------------------------------------------------------------------------------------- |
| Agent    | Read the transcript, send prompts, answer requests, and navigate earlier messages        |
| Editor   | Open files, follow file-and-line links, use language tooling, or run Neovim              |
| Terminal | Run commands in the conversation's working folder                                        |
| Browser  | Preview pages, manage browser state, and send visual comments to the agent               |
| Git      | Review changes, stage files, update the branch, inspect history, and follow PR/MR review |

## Automatic and manual layouts

**Auto layout** opens browser pages and file references beside the agent. It is enabled by default and remembers pane sizes. Manual layout changes are respected, and automatic rearrangements offer undo.

Use the conversation and workspace controls to disable it where needed. Split or resize panes when a different arrangement makes the work easier to inspect.

## Keep the task's context clear

Before the first prompt, check the selected branch and worktree behavior. The task can use a new checkout, reuse one, or work in the project folder. A branch operation may wait until the first prompt starts setup; its pending state is shown in the interface.

The provider and model for a new conversation follow your last accepted manual prompt across projects unless the conversation has an explicit override. Profiles, thinking, modes, and Fast controls appear according to provider capabilities.

## Archive with the cleanup options you intend

Archiving removes a conversation from the active list while preserving its history. The confirmation dialog can optionally include its parent or descendants and shows linked-conversation counts.

Worktree removal, branch removal, and terminal cleanup are separate options when applicable. Review the checked options and any warnings before confirming. Deleting an already archived conversation is a separate permanent action; do not assume it has the same effect as archiving.
