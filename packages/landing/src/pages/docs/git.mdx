## Review working changes

The Changes view separates the changed-file list from the patches, so large diffs can load as needed. Use tree or flat layout, inspect conflicts first, and mark viewed files as you review. Untracked directories expand into individual files.

Stage or unstage each file using its control. Pending operations show progress until Git confirms the state. Open a file in Editor when you need to change it. Review unresolved conflicts and unsaved work before staging.

The nearby diff toolbar controls **Unified/Split** presentation. That preference is shared with Git settings. Image diffs show added, deleted, or before/after previews instead of empty binary panels.

## Inspect history, branches, and stashes

| View                          | What you can inspect                                                            |
| ----------------------------- | ------------------------------------------------------------------------------- |
| Changes                       | Uncommitted files and patches in the working checkout                           |
| Comparison against the target | What this task's branch changes relative to its target                          |
| Commit graph                  | Branch history, individual commits, and commit-level diffs                      |
| Branches                      | Search local/remote branches and inspect their graphs without checking them out |
| Stashes                       | Descriptions, timestamps, file statistics, and the exact saved diff             |

Create a named stash, optionally including untracked files. Existing stashes offer **Apply**, **Pop**, and **Drop**. Apply keeps the stash, Pop applies then removes it when successful, and Drop discards it. Destructive actions require confirmation; conflicts return to the working changes for resolution.

## Update the task branch

The Update controls show the incoming branch and ahead/behind counts. Choose **merge** or **rebase**, then follow the operation's output.

If there are conflicts, open the affected files in Editor. Accept the current side, incoming side, or both as appropriate, review the result, then continue or abort the update. The comparison target comes from the selected source branch; it is not always `main`.

## Commit and push

1. Inspect the diff and stage the intended files.
2. Open Commit and review the selected changes and message.
3. Follow live output while hooks run. Commits can continue in the background so the workspace stays usable.
4. Open Push and check the remote, branch, and exact command shown.

| Push mode        | Effect                                                             |
| ---------------- | ------------------------------------------------------------------ |
| Plain            | Normal push to the remote branch                                   |
| Force with lease | Rewrite only when the remote still matches the expected state      |
| Force            | Force a remote update; inspect the shown command before confirming |

The push dialog supports keyboard submission, live output, background execution, and reopening a running push.

## Connect GitHub or GitLab

Configure the remote-host connection in **Settings → Git → Remote connections**. CadencR supports GitHub pull requests and GitLab merge requests through a shared review workflow. The connection UI reports missing authentication, unavailable tools, or throttling; check those messages when review data cannot load.

Disconnecting a host revokes its stored or CLI-derived access in CadencR. Credentials belong to the exact connected host; a custom GitLab host needs matching authentication.

## Review a pull request or merge request

The sidebar and Git view show proposal and check health. Open the review view to inspect the description, checks, unresolved threads, and inline annotations.

1. Navigate review threads by file or keyboard.
2. Select the comments you want to address, or select all relevant comments.
3. Send the selected review context to the agent.
4. Review the resulting code changes before committing and pushing again.

The **Open compare / PR** action can still open the forge's comparison page. It complements the integrated review workflow.
