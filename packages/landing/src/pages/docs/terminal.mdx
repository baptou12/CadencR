## Start and split a shell

Open **Terminal** in the workspace. Each shell has its own PTY session. Split the pane when you need a server and command prompt side by side; closing or reopening a pane follows the app's persistent session and reconnection behavior.

The pane's context menu offers its available controls. Use [Shortcuts](../shortcuts/) for terminal focus, splitting, pane navigation, copying, and pasting.

## Check the working folder

Shells start in the task's working context. CadencR shows a warning when a shell drifts to another folder.

When a new worktree is created, idle shells can move to it automatically. A busy shell is left running with a warning instead of being killed. Check the folder before running a command that changes files.

## Match your terminal preferences

CadencR uses **CeleriTTY**, a WebGPU terminal backed by Rust/WASM. It reads an available Alacritty configuration for font, colors, cursor, and scrollback, including files loaded through `general.import`. A common configuration path is `~/.config/alacritty/alacritty.toml`; without one, defaults are used.

Colors left unset fall back to your selected CadencR theme. A configuration that only overrides `red` changes exactly that color.

Appearance's **Monospace font** setting also applies across terminals, editor surfaces, and code snippets. Neovim uses the same font family and size resolution. Applicable terminal configuration changes are applied live.

Copy and paste use the terminal selection and paste controls. A terminal canvas is not ordinary page text selection.

## Open links from command output

Use `Cmd/Ctrl` click or the link context menu. Local addresses can open in the conversation's embedded Browser; external links can open in the system browser. The menu also offers open targets and copying.

Listening servers associated with a conversation can appear as port badges in the sidebar. Use those badges to find an active preview without searching old output.

## Terminal, shell prompts, or custom actions?

| Surface                 | Best fit                                                                         |
| ----------------------- | -------------------------------------------------------------------------------- |
| Terminal                | Interactive commands, long-running servers, and manual investigation             |
| Composer `!` shell mode | A supported command whose result should stay in agent context                    |
| Custom action           | A reusable project command, optionally run in a terminal split or at an interval |

## Remote access and cleanup

Paired browser clients can use terminals through [remote access](../remote-access/). Their shell still runs on the host machine.

Archive and delete dialogs offer terminal cleanup when shells are running. Sidebar conversation menus can close a task's terminals and browser tabs without opening it. Inspect the options before confirming cleanup.
